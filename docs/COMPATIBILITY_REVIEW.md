# Compatibility and security review

Reviewed from `2648044` on master. CodeGraph identified the queue, media, storage and pairing paths. Source inspection followed their runtime crossings through Native Messaging, Android intents, TLS, MediaStore and WebAssembly. Builds establish that these paths compile. The [manual acceptance guide](ACCEPTANCE.md) covers registration, actual media offers, playback and device behavior.

## Windows

The standard installation needs Brave, the registered native host and Node. `retrieve` calls `extractedUrls`, which returns immediately when the active host has no extractor directory. Previously a reinstall reused that directory and could silently retain WSL mode. The installer now prepares a fresh generation, validates the Node publisher, compiles the launcher and switches a stable per-user manifest. Older generations occupy disk until removed. [Installer](../apps/desktop/install.ps1) · [Extractor entry point](../apps/desktop/extractor.ts)

The optional signed yt-dlp build runs offline in WSL 2 Ubuntu under bubblewrap. It receives the bounded watch document on stdin. The broker intersects its answer with directly offered URLs. A missing namespace facility or worker failure ends that attempt. This mode cannot recover formats absent from the original document. [Worker and prerequisites](EXTRACTOR.md)

A native offline Python extractor is feasible in principle. It would need a Windows AppContainer with no network capabilities, read access scoped to a pinned runtime and its assets, explicitly inherited pipes, and a Job Object with memory, process and lifetime limits. A Job Object alone provides no outbound-network policy. Packaging Python and proving the file, handle and socket boundaries on supported Windows versions would add a new trusted component without increasing this extractor's set of eligible formats. The reviewed build therefore keeps the native default and the existing opt-in isolated extractor. [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) · [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## Media selection and limits

Both brokers reconstruct a watch URL from a validated ID and require an OK public, non-live response with matching identity. MP4 needs one direct progressive AVC/AAC stream at or below the chosen height. MP3 needs one directly offered Opus/WebM input. Separate video-only and audio-only offers cannot produce an MP4 here. A 1080p selection may produce a lower available resolution. A public, playable page can still require a challenge or withhold every supported URL. No success rate was measured. [Windows selection](../apps/desktop/media.ts) · [Android selection](../apps/android/app/src/main/java/org/downloadit/app/Media.kt) · [Upstream format selection](https://github.com/yt-dlp/yt-dlp#format-selection)

The receiving broker skips candidates whose declared size exceeds its budget. An exact size from the format descriptor can replace a missing HTTP Content-Length. Conflicting, invalid or entirely missing declarations fail. Successful publication requires the actual byte count to match. For direct MP4 the broker also checks MIME type and the initial file-type box. Playback and the actual tracks still need verification in a player.

| Receiver setting | Streamed MP4 | MP3 at 128 / 192 / 320 kbps |
|---|---|---|
| Standard | 256 MiB and one hour | 15 / 15 / 15 minutes |
| Extended | 512 MiB and two hours | 37 min 30 s / 25 min / 15 min |

Extended MP3 spends the same nominal 36 MB of encoded audio at each bitrate. The converter also counts actual decoded samples, caps Opus input at 16 MiB and encoded output at 37 MiB, bounds WebAssembly linear memory to 128 MiB and applies a conversion deadline. Available storage, network time and CPU speed can end a job earlier. MP4 duration comes from the watch document. Its transfer size is enforced on actual bytes. Windows selects the profile at installation. Android reads its own preference on each attempt, including paired requests. [Audio budget](../packages/core/limits.ts) · [Encoder](../packages/core/audio.ts) · [Installation switches](INSTALLATION.md)

**Separate-track merging.** Stream-copying compatible tracks into MP4 could avoid re-encoding. Android supplies MediaExtractor and MediaMuxer. The current shared conversion path demuxes WebM and writes MP3. Neither platform has a reviewed two-track pipeline. Enabling one would require two independently approved direct URLs for the same video, isolated container parsing, verified clear AVC/AAC track types, valid timing and A/V sync, a combined input/scratch/output budget and cancellation-safe finalization. Until those conditions can be verified on devices, an adaptive-only video yields an unavailable result. [Android MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer) · [libav.js variants](https://github.com/Yahweasel/libav.js#variants)

## Android

MP4 is copied by Kotlin independently of WebView. For MP3, `encodeAudio` checks JavaScriptSandbox support and the actual provider's WebAssembly, named-data, promise, isolate termination and heap-limit features. An API 29+ installation alone cannot establish MP3 support. Media and metadata enter the isolate as data. The decoder loads packaged code and a hash-verified Wasm image. [Codec path](../apps/android/app/src/main/java/org/downloadit/app/Audio.kt) · [AndroidX JavaScriptSandbox](https://developer.android.com/reference/androidx/javascriptengine/JavaScriptSandbox)

The broker inserts a pending row into the primary external audio or video collection, writes the chosen MIME type and relative folder, closes the stream, and clears the pending flag on successful completion. Default folders are `Music/DownloadIT/` and `Movies/DownloadIT/`. Cancellation, retry and clearing history now retain the URI until cleanup is confirmed. Startup recovery checks both collection and row ID before deleting a still-pending entry. The system insert and the app's first journal write are separate transactions. Process death between them can leave a hidden pending row subject to provider expiration. Check MediaStore publication separately from Pulsar, Gallery or VLC visibility and playback. [Media writer](../apps/android/app/src/main/java/org/downloadit/app/Media.kt) · [Job journal](../apps/android/app/src/main/java/org/downloadit/app/Jobs.kt) · [Shared media storage](https://developer.android.com/training/data-storage/shared/media)

**Can a paired phone receive a new download while hidden?** No. The user opens the receiver on private Wi-Fi. Leaving the activity, losing the selected default network or losing its bound address closes it and invalidates the QR. An already accepted job can continue in the user-visible dataSync foreground service, subject to OS limits. On Android 15+ for apps targeting API 35+, background dataSync service time is limited to six hours per 24 hours across the app. The service handles the system timeout and is non-sticky. A persistent idle listener cannot assume this service type or unrestricted background starts. A future background receiver would need a separately justified platform mechanism, explicit opt-in, visible stop control, expiry and revocation. A QR credential alone grants no Android background execution privilege. [Receiver](../apps/android/app/src/main/java/org/downloadit/app/PeerServer.kt) · [Download service](../apps/android/app/src/main/java/org/downloadit/app/DownloadService.kt) · [Service types](https://developer.android.com/develop/background-work/services/fgs/service-types) · [Background-start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) · [Timeouts](https://developer.android.com/develop/background-work/services/fgs/timeout)

## Security boundaries

| Boundary | Controls traced in source | Remaining exposure or acceptance item |
|---|---|---|
| Website → extension → Windows host | Trusted top-frame click, supported YouTube origins, active video checks, separate confirmation, bounded and validated IPC. MV3 requests storage and Native Messaging. Installer and launcher restrict the extension identity. | A website can mislead a user. Verify selected video, fixed extension ID and per-user registration. [Manifest](../apps/extension/manifest.json) · [Background](../apps/extension/background.ts) · [Launcher](../apps/desktop/Launcher.cs) |
| Broker → Internet | HTTPS only, exact watch and media paths, single-label googlevideo CDN hosts and a fixed cover path. Reject redirects, credentials, fragments, nonstandard ports and special-use IPv4 answers. Windows resolves once, dials the vetted numeric address and retains the DNS name for TLS. Android uses a network-bound socket factory and DNS, rejects unsafe IPv4 answers, and disables proxies and redirects. | IPv4 connectivity and public offers are required. The intentional LAN pairing endpoint has a separate policy. [Desktop network](../apps/desktop/network.ts) · [Android network](../apps/android/app/src/main/java/org/downloadit/app/Media.kt) |
| Codec → OS | Windows launches a bounded child with fixed arguments, a narrow read path and local Wasm/virtual files. Only the trusted glue supplies Wasm imports. Android uses the system isolated JS process. The optional Python extractor has a separate network namespace. | Windows Node permissions and disabled fetch do not establish a process-wide OS network sandbox. Trust in the pinned JS glue and runtime is material. Strong containment of compromised host code would require an OS sandbox. [Child launcher](../apps/desktop/encode.ts) · [Node permission model](https://nodejs.org/download/release/v24.13.0/docs/api/permissions.html) |
| PC → phone | A one-use, 90-second QR bootstraps TLS 1.3 with exact server certificate pinning. Each connection gets a fresh nonce and carries one operation. Android Keystore holds the identity key, Android stores a verifier of each random bearer credential, and Windows uses current-user DPAPI for its vault. Up to eight peers. | An authorized PC can manage the phone's entire queue. Credential theft allows fresh authenticated requests until phone-side revocation. Forgetting a device on Windows removes the local record. Camera, TLS provider and revocation require two devices. [Windows peer client](../apps/desktop/peers.ts) · [Android peer server](../apps/android/app/src/main/java/org/downloadit/app/PeerServer.kt) |
| Job → disk and CPU | One active job per receiver, up to 64 retained entries and three attempts per job. Windows checks approved real directories, creates exclusive temporary files and uses a no-overwrite hard link. Android accepts a restricted subfolder name and publishes through MediaStore. Both enforce byte counts and check free space. | Space can change after a preflight check. Windows redirected folders and filesystems without hard links can fail. Same-account malware and OS compromise are outside the boundary. [Windows queue](../apps/desktop/queue.ts) · [Android jobs](../apps/android/app/src/main/java/org/downloadit/app/Jobs.kt) |
| Dependencies → package | Frozen pnpm graph, locked Gradle artifacts, verification metadata and wrapper checksum. Codec build checks original JS and Wasm digests before narrowing the memory declaration. Optional extractor preparation checks an upstream signature and digest. | Artifact integrity does not establish package safety. Preserve QR and embedded component notices. A binary release needs the exact codec build configuration, corresponding sources and local modification, replacement/rebuild instructions, artifact inventory and owner signing. [Codec build](../packages/core/build-audio.mjs) · [Third-party notices](../THIRD_PARTY_NOTICES.md) · [Release procedure](RELEASE.md) · [FFmpeg licensing](https://ffmpeg.org/legal.html) |

The review added no runtime dependency or permission. Physical Windows/Android installation, the optional WSL isolation path, live transfers, player indexing, pairing and foreground-service behavior remain acceptance items.
